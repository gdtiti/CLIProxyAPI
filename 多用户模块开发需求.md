# CLI Proxy API 多用户模块开发需求手册

## 1. 项目背景与目标

### 1.1 项目背景

当前 CLI Proxy API 是一个 AI 代理服务，支持多种 AI 供应商（Gemini、Claude、Codex、Kiro 等）的统一接入。现有系统采用配置文件（YAML）和文件系统存储认证信息，适合单用户或小团队使用场景。

为了支持商业化部署和多租户场景，需要开发多用户模块，实现：
- 用户和用户组管理
- 基于用户的资源访问控制
- 按量计费和余额管理
- API Key 管理和使用统计

### 1.2 核心目标

1. **多租户支持**：支持管理员管理多个用户和用户组
2. **资源访问控制**：精细化控制用户可访问的 AI 供应商和模型
3. **计费系统**：实现基于 Token 的计费和余额扣减
4. **API Key 管理**：用户可自主管理多个 API Key
5. **统计分析**：提供详细的使用统计和扣费记录

#### 4.1.1 功能清单

| 功能 | 描述 | 优先级 |

```go
// internal/multiuser/middleware/auth.go
func MultiUserAuthMiddleware(
    apiKeyService APIKeyService,
    permissionService PermissionService,
    billingService BillingService,
) gin.HandlerFunc {
    return func(c *gin.Context) {
        // 1. 提取 API Key
        apiKey := extractAPIKey(c)
        if apiKey == "" {
            c.AbortWithStatusJSON(401, gin.H{"error": "missing api key"})
            return
        }
        
        // 2. 验证 API Key
        validation, err := apiKeyService.ValidateAPIKey(c.Request.Context(), apiKey)
        if err != nil || !validation.Valid {
            c.AbortWithStatusJSON(401, gin.H{"error": "invalid api key"})
            return
        }
        
        // 3. 检查权限
        model := extractModel(c)
        provider := resolveProvider(model)
        allowed, err := permissionService.CheckPermission(c.Request.Context(), &CheckPermissionRequest{
            UserID:       validation.UserID,
            APIKeyID:     validation.APIKeyID,
            ResourceType: ResourceModel,
            ResourceID:   model,
            Action:       ActionAllow,
        })
        if err != nil || !allowed {
            c.AbortWithStatusJSON(403, gin.H{"error": "permission denied"})
            return
        }
        
        // 4. 余额预检 (可选，流式请求后置扣费)
        // ...
        
        // 5. 设置上下文
        c.Set("user_id", validation.UserID)
        c.Set("api_key_id", validation.APIKeyID)
        c.Set("permissions", validation.Permissions)
        
        c.Next()
        
        // 6. 请求完成后计费 (在 usage plugin 中处理)
    }
}
```

```go
// internal/multiuser/plugin/billing_plugin.go
type BillingPlugin struct {
    billingService  BillingService
    analyticsService AnalyticsService
}

func (p *BillingPlugin) HandleUsage(ctx context.Context, record coreusage.Record) {
    // 从上下文获取用户信息
    userID := getUserIDFromContext(ctx)
    apiKeyID := getAPIKeyIDFromContext(ctx)
    
    if userID == "" {
        return // 非多用户模式请求
    }
    
    // 计算费用
    cost, err := p.billingService.CalculateCost(ctx, &CalculateCostRequest{
        UserID:          userID,
        Provider:        record.Provider,
        Model:           record.Model,
        InputTokens:     record.Detail.InputTokens,
        OutputTokens:    record.Detail.OutputTokens,
        CachedTokens:    record.Detail.CachedTokens,
        ReasoningTokens: record.Detail.ReasoningTokens,
    })
    if err != nil {
        log.Errorf("failed to calculate cost: %v", err)
        return
    }
    
    // 扣减余额
    usageRecord := &UsageRecord{
        UserID:          userID,
        APIKeyID:        apiKeyID,
        RequestID:       generateRequestID(),
        Provider:        record.Provider,
        Model:           record.Model,
        InputTokens:     record.Detail.InputTokens,
        OutputTokens:    record.Detail.OutputTokens,
        TotalTokens:     record.Detail.TotalTokens,
        InputCost:       cost.InputCost,
        OutputCost:      cost.OutputCost,
        TotalCost:       cost.TotalCost,
        Status:          resolveStatus(record.Failed),
        RequestedAt:     record.RequestedAt,
    }
    
    if err := p.billingService.DeductBalance(ctx, userID, cost.TotalCost, usageRecord); err != nil {
        log.Errorf("failed to deduct balance: %v", err)
    }
    
    // 记录使用日志
    if err := p.analyticsService.RecordUsage(ctx, usageRecord); err != nil {
        log.Errorf("failed to record usage: %v", err)
    }
}
```

## 11. 安全考虑

### 11.1 认证安全

- 密码使用 bcrypt 加密存储 (cost >= 12)
- JWT Token 使用 HS256/RS256 签名
- Refresh Token 支持单点登出
- 登录失败次数限制和账户锁定
- OAuth state 参数防止 CSRF 攻击
- 第三方 Token 加密存储

### 11.2 API Key 安全

- Key 使用 SHA-256 哈希存储，原文仅创建时返回一次
- 支持 IP 白名单限制
- 支持过期时间设置
- 支持即时撤销

### 11.3 注册安全

- 邮箱验证防止虚假注册
- 邮箱域名黑名单阻止临时邮箱
- IP 频率限制防止批量注册
- 可选的管理员审核机制
- 邀请码控制注册入口

### 11.4 数据安全

- 敏感字段加密存储
- 数据库连接使用 SSL/TLS
- 审计日志记录关键操作
- 定期数据备份

### 11.4 访问控制

- 基于角色的访问控制 (RBAC)
- 最小权限原则
- 权限变更即时生效
- 管理操作需要二次确认

### 13.1 错误码定义

| 错误码 | 描述 | HTTP 状态码 |
|--------|------|-------------|
| `AUTH_INVALID_CREDENTIALS` | 用户名或密码错误 | 401 |

| `APIKEY_INVALID` | API Key 无效 | 401 |
| `APIKEY_EXPIRED` | API Key 已过期 | 401 |
| `APIKEY_REVOKED` | API Key 已撤销 | 401 |
| `APIKEY_QUOTA_EXCEEDED` | API Key 额度已用尽 | 402 |
| `PERMISSION_DENIED` | 权限不足 | 403 |
| `PROVIDER_NOT_ALLOWED` | 供应商访问被拒绝 | 403 |
| `MODEL_NOT_ALLOWED` | 模型访问被拒绝 | 403 |
| `BALANCE_INSUFFICIENT` | 余额不足 | 402 |
| `RATE_LIMIT_EXCEEDED` | 请求频率超限 | 429 |
| `USER_NOT_FOUND` | 用户不存在 | 404 |
| `USER_SUSPENDED` | 用户已暂停 | 403 |
| `USER_DISABLED` | 用户已禁用 | 403 |
