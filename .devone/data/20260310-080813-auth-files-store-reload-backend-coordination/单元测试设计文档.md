## 测试目标

- 需要被保护的核心行为:
  上传 auth file 时，当前节点不能只更新本地文件和内存，还必须同步调用 store
  持久化能力。
- 这轮必须覆盖的失败模式:
  store 持久化失败后接口仍返回 200，或当前节点已经注册了新 auth 但共享 store
  仍是旧数据。

## 单元测试设计

### UT-001

- 目标:
  验证 multipart 上传成功时会同步调用 store persister，并把当前节点
  `authManager` 与列表接口刷新到最新值。
- 覆盖函数/模块:
  `UploadAuthFile`、`persistUploadedAuthFile`、`registerAuthFromFile`
- 输入:
  multipart form 上传一个带 `type/email/prefix/proxy_url/priority` 的 auth JSON。
- 预期输出:
  返回 200；`PersistAuthFiles` 被调用一次；auth file 写入本地目录；当前节点
  `authManager` 与 `GET /auth-files` 均能看到最新字段。
- 失败表现:
  store 未被调用，或列表/运行态仍然看不到上传后的真实值。

### UT-002

- 目标:
  验证 raw JSON 上传在 store 持久化失败时返回错误，并恢复上传前文件内容。
- 覆盖函数/模块:
  `UploadAuthFile`、`persistUploadedAuthToStore`、失败回滚逻辑
- 输入:
  raw JSON 上传到一个已有 auth file 名称，store persister 返回错误。
- 预期输出:
  返回 500；manager 不会注册新 auth；原文件内容被恢复。
- 失败表现:
  接口返回成功、manager 被污染，或本地文件停留在失败上传的新内容。
