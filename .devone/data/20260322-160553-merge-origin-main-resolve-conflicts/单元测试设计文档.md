## 测试目标

- 需要被保护的核心行为:
  在不引入无意义代码改动的前提下，正确判断 `origin/main` 是否需要合并。
- 这轮必须覆盖的失败模式:
  把“已是最新”误判成“存在冲突”，或在无冲突时误进入代码层修改。

## 单元测试设计

### UT-001

- 目标:
  验证当前分支与 `origin/main` 的差异是否为零。
- 覆盖函数/模块:
  git 差异统计与 merge 命令输出。
- 输入:
  `git rev-list --left-right --count origin/main...HEAD`
  `git merge origin/main`
- 预期输出:
  差异统计左侧为 `0`，merge 返回 `Already up to date.`。
- 失败表现:
  若出现待合并提交或冲突标记，则必须转入逐文件解决。

- 不变量:

- 预期失败模式:
  merge 现场残留冲突文件或索引状态异常。
