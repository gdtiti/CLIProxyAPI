## 测试目标

- 需要被保护的核心行为:
  - Codex 429 会把整份 auth 临时禁用 5 小时。
  - 禁用期间 selector/scheduler 不会再次选中该 auth。
  - 到期后 auth 自动恢复，不需要手工 enable。
  - 非 Codex 或非 429 不会触发该禁用逻辑。
- 这轮必须覆盖的失败模式:
  - `StatusDisabled` 被当成永久禁用，导致到期后仍不可用。
  - scheduler 因 auth 被完全移除而无法自动恢复。
  - 重启或持久化回放后丢失剩余禁用时间。

## 单元测试设计

### UT-001

- 目标: 验证 `Manager.Execute/MarkResult` 在 Codex 429 后把 auth 标记为 5 小时临时禁用。
- 覆盖函数/模块: `sdk/cliproxy/auth/conductor.go`
- 输入: `provider=codex`、`status=429`、带任意 `RetryAfter/QuotaWindow` 的执行错误。
- 预期输出: auth 进入临时禁用态；`NextRetryAfter` 接近 `now+5h`；当前 model 与 global model 在禁用期内不可选。
- 失败表现: auth 仍为普通 quota cooldown、或者禁用时间不是 5 小时。

### UT-002

- 目标: 验证临时禁用在到期后会自动恢复选择。
- 覆盖函数/模块: `sdk/cliproxy/auth/selector.go` 或相关 helper
- 输入: 一个带过期临时禁用元数据、已超过 `NextRetryAfter` 的 Codex auth。
- 预期输出: 选择器不再把该 auth 视为 disabled/cooldown。
- 失败表现: 到期后仍返回 `auth_unavailable` 或继续跳过该 auth。

### UT-003

- 目标: 验证非 Codex 或非 429 不触发临时禁用。
- 覆盖函数/模块: `sdk/cliproxy/auth/conductor.go`
- 输入: 401、403 或其它 provider 的 429。
- 预期输出: 沿用原有状态流转，不写入临时禁用标记。
- 失败表现: 无关错误也把 auth 拉黑 5 小时。

## 属性测试设计

### PT-001

- 性质: 临时禁用到期前始终不可选，到期后可重新参与选择。
- 输入空间: `now`、`disableUntil`、请求模型名、是否存在 global model state。
- 不变量: `now < disableUntil` 时 blocked；`now >= disableUntil` 时不再因临时禁用而 blocked。
- 预期失败模式: 只处理当前模型、不处理全 auth，或到期判断受 `StatusDisabled` 残留影响。

## 测试夹具与数据策略

- 夹具: 复用现有 `testCodexQuotaExecutor`、`Result` 回写测试模式和 selector 单测夹具。
