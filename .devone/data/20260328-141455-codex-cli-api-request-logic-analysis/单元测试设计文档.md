## 测试目标

- 需要被保护的核心行为:
  - 模型 `SupportedEndpoints` 驱动的 `/chat/completions` 与 `/responses` 自动切换。
  - Chat -> Codex 请求转换时的固定字段写入与消息/工具映射。
  - Codex HTTP / WS 执行器对头部、会话字段和清洗字段的处理。
  - payload 规则对 `protocol=codex` 的 default/override/filter 生效顺序。
- 这轮必须覆盖的失败模式:
  - 模型只支持 `/responses` 却仍走 `/chat/completions`。
  - `reasoning_effort`、tool mapping 或 `store=false` 被回归破坏。
  - WebSocket 未优先挑选 `websockets=true` 的 auth。
  - 版本头已更新但 `OpenAI-Beta` / `x-codex-beta-features` 行为未同步。

## 单元测试设计

### UT-001

- 目标: 验证 endpoint override 按模型能力切换。
- 覆盖函数/模块: `sdk/api/handlers/openai/endpoint_compat.go`
- 输入: 支持 `["/responses"]`、`["/chat/completions"]`、`["/chat/completions","/responses"]` 的模型信息。
- 预期输出: 只在当前端点不受支持且另一端点受支持时返回 override。
- 失败表现: 误切换或漏切换，导致路由到错误上游。

### UT-002

- 目标: 验证 Chat -> Codex 的固定字段和消息映射。
- 覆盖函数/模块: `internal/translator/codex/openai/chat-completions/codex_openai_request.go`
- 输入: 含 system/user/assistant/tool/tool_calls 的 OpenAI Chat 请求。
- 预期输出: `system -> developer`、`tool -> function_call_output`、assistant `tool_calls -> function_call`，且包含 `parallel_tool_calls`、`reasoning.summary`、`include`、`store=false`。
- 失败表现: 工具调用链断裂或固定字段丢失。

### UT-003

- 目标: 验证 Codex 执行器清洗字段与 header 默认值。
- 覆盖函数/模块: `internal/runtime/executor/codex_executor.go`、`internal/runtime/executor/codex_websockets_executor.go`
- 输入: 含 `previous_response_id`、`prompt_cache_retention`、`safety_identifier` 的请求，以及有/无 config header defaults 的上下文。
- 预期输出: 三个字段被删除；HTTP / WS 头部按客户端头 > 配置默认值 > 硬编码默认值的顺序生效。
- 失败表现: 上游收到不该透传的字段，或版本头未按预期注入。
