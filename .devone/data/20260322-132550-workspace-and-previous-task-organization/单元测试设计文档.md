## 测试目标

- 需要被保护的核心行为:
  历史任务与 worktree 的映射必须准确，当前继续入口必须可复原。
- 这轮必须覆盖的失败模式:
  把主工作区改动归到错误任务、误判某个 worktree 已可删除、或在整理过程中引入新的业务代码改动。

## 单元测试设计

### UT-001

- 目标:
  验证历史任务包清单与阶段状态被完整收集。
- 覆盖函数/模块:
  `.devone/data/*/任务跟踪列表.md`
- 输入:
  读取 4 个历史任务包的 `任务跟踪列表.md` 元信息与任务块状态。
- 预期输出:
  能明确区分 4 个任务包的阶段状态，并识别出 `20260310-183634` 与 `20260318-172541` 为重点历史任务。
- 失败表现:
  遗漏任务包、阶段状态记录错误，或把已停滞 discovery 的任务误判为当前主线。

### UT-002

- 目标:
  验证主工作区与各 worktree 的干净度、HEAD 和脏文件集合。
- 覆盖函数/模块:
  `git status --short --branch`
  `git worktree list`
  `git -C <worktree> status --short --branch`
  `git diff --name-only`
- 输入:
  主工作区与两个 worktree 的 git 现场。
- 预期输出:
  `20260310-183634` worktree 干净；
  `20260318-172541` worktree 与主工作区同一 HEAD；
  主工作区脏文件是该 worktree 脏文件集合的子集。
- 失败表现:
  无法说明继续入口，或误认为主工作区改动与历史任务无关。

### UT-003

- 目标:
  验证本轮整理没有修改业务代码，也没有执行危险清理。
- 覆盖函数/模块:
  当前仓库 git 状态与变更范围。
- 输入:
  整理前后的 git 状态。
- 预期输出:
  仅新增当前整理任务包文档；业务代码脏改动保持原状；没有文件删除或分支合并。
- 失败表现:
  新增业务代码改动、删除目录，或改变现有 worktree 结构。

## 属性测试设计
### PT-001

- 性质:
  在仓库状态不发生新变化时，重复执行同一组盘点命令应得出同一任务映射结论。
- 输入空间:
  当前仓库、当前 4 个任务包、当前 2 个 worktree。
- 不变量:
  `20260318-172541` 仍是当前继续入口；
  `20260310-183634` 仍是待收尾旧任务；
  主工作区 dirty 文件集合保持为前述 4 个核心文件。
- 预期失败模式:
  因读取来源不一致导致结论漂移。

## 测试夹具与数据策略
- 夹具:
  直接使用当前仓库真实 `.devone`、真实 git 状态和真实 worktree。
- 真实数据策略:
  不引入 mock，不伪造任务包，不复制临时快照替代当前现场。
- 禁止使用的假路径:
  不允许构造“假 clean”工作区，不允许臆测已删除或已合并的状态。
