## 术语与定义

- warm：由真实成功请求驱动的短期保活窗口，当前通过 `MarkResult()` 写入 `WarmUntil`。
- resident：由虚拟池/常驻池等上游策略驱动的预热窗口，本轮要桥接到 `ResidentUntil`。
- resident hint：selector 暴露给 manager 的轻量抽象，用于描述“哪些 auth 此刻应视为 resident”。

## 调研结论

- 结论 1:
  - 第二波最安全的桥接点不在 `shouldRefresh()`，而在 selector 已完成选路、manager 即将返回 selected auth 的收口点；这样 resident 仍先沉淀到 `Auth` 运行态，再被 refresh gate 消费。
- 结论 2:
  - 若直接在 selector 内部写 `Auth.ResidentUntil`，会把 selector 私有并发边界和 manager 共享 auth 状态混在一起；更稳妥的是“selector 产出 hint，manager 持锁落地”。
- 结论 3:
  - resident bridge 只需要覆盖 `provider=codex`；其它 provider 即使使用 SimHash selector，也不应因为本轮桥接而改变 refresh 语义。
