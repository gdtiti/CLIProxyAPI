## 测试目标

- 需要被保护的核心行为:
  - cold Codex auth 不再因 `RefreshLead=5d` 在后台扫描中被无条件刷新。
  - warm Codex auth 在最近使用窗口内仍能进入后台 refresh。
  - disabled / temporary disabled / `NextRefreshAfter` 等既有短路条件不退化。
  - 请求成功后能正确写入运行态热度字段。
- 这轮必须覆盖的失败模式:
  - 热度字段未更新导致 warm auth 无法 refresh。
  - warm gate 漏判导致 cold auth 继续每轮刷新。
  - 新逻辑覆盖掉 disabled/temporary disable 优先级。

## 单元测试设计

### UT-001

- 目标:
  - 验证 cold Codex auth 不会因 lead 逻辑进入 refresh。
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/conductor.go` / `Manager.shouldRefresh()`
- 输入:
  - provider=`codex`，auth 带未来 `expired`，无 `LastUsedAt/WarmUntil`，无 disabled/next refresh after
- 预期输出:
  - `shouldRefresh()` 返回 `false`
- 失败表现:
  - 仍返回 `true`，说明后台 refresh 仍可能 15 分钟全刷。

### UT-002

- 目标:
  - 验证 warm Codex auth 仍可 refresh。
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/conductor.go` / `Manager.shouldRefresh()`
- 输入:
  - provider=`codex`，auth 带未来 `expired`，`WarmUntil > now`
- 预期输出:
  - `shouldRefresh()` 返回 `true`
- 失败表现:
  - 返回 `false`，说明活跃 auth 被错误冷落。

### UT-003

- 目标:
  - 验证请求成功后会写入热度字段。
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/conductor.go` / `Manager.MarkResult()`
- 输入:
  - 模拟成功请求结果
- 预期输出:
  - `LastUsedAt` 被刷新，`WarmUntil` 大于 `LastUsedAt`
- 失败表现:
  - 热度字段保持零值或窗口不递增。

### UT-004

- 目标:
  - 验证 disabled / temporary disable 短路优先级不退化。
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/conductor.go` / `Manager.shouldRefresh()`
- 输入:
  - warm auth + disabled 或 temporary disable 条件
- 预期输出:
  - `shouldRefresh()` 返回 `false`
- 失败表现:
  - 热度字段覆盖了既有安全短路逻辑。

### UT-005

- 目标:
  - 验证 refresh/update 后不会丢失 warm/resident 运行态字段。
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/conductor.go` / `preserveRuntimeAuthState()`
- 输入:
  - 已带热度字段的旧 auth + 不带热度字段的新 auth 更新
- 预期输出:
  - `LastUsedAt/WarmUntil/ResidentUntil` 保留
- 失败表现:
  - 更新后热度字段被清零，导致下一轮后台 refresh 误判为 cold。
