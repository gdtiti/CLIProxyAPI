## 实际改动摘要

- 本轮改动: 管理端 `UploadAuthFile` 统一走持久化函数，增加校验 -> 写盘 -> store 持久化 -> 注册，失败时回滚本地文件；补入上传路径单元测试。
- 本轮改动: 新增 `POST /v0/management/auth-files/batch`，支持多选文件与 zip 导入，复用单文件持久化/校验链路。
- 本轮改动: 合并主工作区残留的运行态持久化逻辑，新增 `sdk/cliproxy/auth/runtime_persistence.go`，并接入 `filestore`、`synthesizer`、`conductor`。
- 本轮改动: 为 Codex 增加 `id_token -> account_id` 共用 helper，并接到文件合成与 refresh 路径；补入 JWT helper 测试。
- 本轮改动: 新增管理端 auth runtime hook；401 改为“10 分钟内连续 3 次（可配置）后自动处置”，普通文件直接删除，Gemini 先移除虚拟 project，移空后才删真实文件。
- 本轮改动: watcher 启动时移除一次冗余 auth 目录预扫描，改为在重建 hash/cache 时一次性完成统计与缓存构建。
- 涉及文件/模块: `internal/api/handlers/management/auth_files.go`、`internal/api/handlers/management/auth_files_batch.go`、`internal/api/handlers/management/auth_files_runtime_hook.go`、`internal/api/handlers/management/auth_files_upload_test.go`、`internal/api/handlers/management/auth_files_runtime_hook_test.go`、`internal/api/server.go`、`internal/config/config.go`、`internal/watcher/clients.go`、`internal/watcher/synthesizer/file.go`、`internal/watcher/synthesizer/file_test.go`、`sdk/auth/filestore.go`、`sdk/auth/filestore_test.go`、`sdk/cliproxy/auth/conductor.go`、`sdk/cliproxy/auth/conductor_quota_integration_test.go`、`sdk/cliproxy/auth/runtime_persistence.go`

### Wave 2

- 目标: 合并主工作区残留改动，并补齐批量上传 / 401 自动处置 / Codex 冷却持久化恢复 / 启动扫描优化
- 改动:
  - 将主工作区中的运行态持久化恢复逻辑并入 worktree：`filestore` 读取时恢复、`synthesizer` 合成时恢复、`conductor` 持久化前同步 metadata
  - `conductor` 中 401 不再首次直接 `disabled`；新增 hook 组合能力，为管理端自动处置挂钩
  - 新增 `auth-runtime` 配置段，支持 `unauthorized-delete-threshold` / `unauthorized-delete-window-seconds`
  - 管理端新增 `UploadAuthFilesBatch`，支持 multipart 多文件与 zip 扩展导入
  - 管理端新增 401 自动处置 hook：达到阈值后普通文件直接删除，Gemini 仅移除命中的虚拟 project，并通过 reload 让剩余 project 继续可用
  - `reloadClients` 改为一次扫描同时完成计数、hash、内容缓存与 file synthesize 缓存，去掉启动期一轮纯计数扫描
- 结果:
  - 批量上传、401 自动处置、Gemini 虚拟删除顺序、Codex 冷却恢复与 watcher 启动扫描优化代码已落地
