## 测试目标

- 需要被保护的核心行为: 批量上传在校验/持久化/运行态刷新上的一致性与可回滚性。
- 这轮必须覆盖的失败模式: 批量导入部分失败时不污染 authDir；store 持久化失败时可恢复。

## 单元测试设计

### UT-001

- 目标: 批量上传成功路径能写入 authDir，并在可用时持久化到 store，再触发一次性 reload。
- 覆盖函数/模块: 新批量 handler + 复用 `persistUploadedAuthFile`/批量持久化封装。
- 输入: 多文件请求（zip 或 multipart）。
- 预期输出: 返回逐文件成功报告，authDir 与 store 一致。
- 失败表现: 任一失败导致未回滚或错误码不正确。

### UT-002

- 目标: 批量导入出现失败时符合“原子性/部分成功”策略。
- 覆盖函数/模块: 批量校验与回滚逻辑。
- 输入: 混合合法/非法文件集。
- 预期输出: 按策略返回失败清单，authDir 状态正确。
- 失败表现: 产生半写入且无明确错误报告。

### UT-003

- 目标: 启动扫描优化后，authDir 全量扫描次数减少且结果一致。
- 覆盖函数/模块: `internal/watcher/clients.go` 与 `internal/watcher/synthesizer/file.go` 相关重构点。
- 输入: 固定 authDir 样例集。
- 预期输出: 统计扫描次数下降，最终合成结果一致。
- 失败表现: 扫描次数未下降或运行态结果不一致。

### UT-004

- 目标: 认证请求返回 401 时按策略自动处置（10 分钟内连续 3 次），且阈值可配置。
- 覆盖函数/模块: 401 处理逻辑与删除/禁用入口。
- 输入: 触发 401 的请求样例与对应 auth 文件（含阈值配置）。
- 预期输出: 仅当满足阈值时删除或禁用，避免误删。
- 失败表现: 触发条件不正确或误删。

### UT-005

- 目标: Gemini 虚拟凭证删除策略符合“先删虚拟、虚拟全清后才删真实”。
- 覆盖函数/模块: Gemini 相关认证文件管理逻辑。
- 输入: 多个虚拟凭证 + 真实凭证的组合。
- 预期输出: 虚拟凭证逐个删除，最后才删除真实凭证。
- 失败表现: 虚拟凭证未清空就删除真实凭证。

### UT-006

﻿- 目标: 配额查询为 0 且需冷却时自动禁用对应证书，冷却时间以配额查询返回为准，并在冷却到期后恢复可用；覆盖 Codex usage 的 reset_after_seconds/reset_at 解析。
- 覆盖函数/模块: 配额检查与禁用逻辑 + Codex usage 解析（`internal/runtime/executor/codex_executor.go`, `internal/runtime/executor/usage_helpers.go`）。
- 输入: 配额为 0 且带冷却的响应（Codex usage reset_after_seconds/reset_at、Qwen 次日 00:00、Gemini CLI/Antigravity retryDelay）；Codex 缺失 access_token/account_id 的降级场景。

- 失败表现: 仍继续使用证书、禁用范围错误或无法恢复。

## 属性测试设计

### PT-001

- 性质: 对同一批输入文件重复导入，结果应保持幂等或可预测（无重复/无丢失）。
- 输入空间: 不同文件数量、大小、包含重复文件名的组合。
- 不变量: authDir 与 store 的最终集合一致。
- 预期失败模式: 重复导入后出现丢失或重复条目。

## 测试夹具与数据策略

- 夹具: 临时 authDir、最小合法 auth 文件样例、伪造 token store（必要时使用内存实现）。
- 真实数据策略: 选取 3-5 份真实样例做边界验证。
- 禁止使用的假路径: 仅 mock HTTP 层而不验证写盘与 reload 结果。
