## 问题定义

- 当前问题: 认证文件仅支持单文件上传，批量导入需要重复调用接口，耗时且一致性差；启动阶段对 authDir 多次全量扫描/解析，导致启动变慢。
- 影响对象: 管理端批量导入用户、运维与部署启动窗口、需要频繁更新 auth 文件的团队。
- 触发背景: auth 文件数量增长（百级/千级）或频繁换批次；认证文件请求出现 401 需要自动处置；查询配额发现 0 且需冷却时希望自动禁用。
- 为什么现在处理: 已影响部署效率与可用性，且当前缺少批量入口与启动优化方案；自动处置规则缺失易导致故障扩散。

## 目标与成功标准

﻿- 目标 1: 明确批量上传输入规范（多文件与 zip）、校验/回滚策略、与 store/运行态 reload 的一致性规则，并形成可实现设计与验收标准。
- 目标 2: 定位启动链路中的重复扫描点，给出可执行优化方案与验证方法（启动耗时/IO 下降）。
- 目标 3: 定义 401 自动处置策略（含 Gemini 虚拟凭证规则）与配额为 0 的自动禁用策略。
- 目标 4: 明确各 provider 配额/冷却来源差异，优先 Codex 认证文件字段配合与冷却刷新设计。
- 成功标准（性能）: 服务启动耗时目标 <= 60s。
- 成功标准（规则）: Codex 认证文件字段要求（access_token + account_id）已明确并写入设计；各 provider 冷却/退避来源形成清单。
