## 测试目标

- 需要被保护的核心行为:
  - distributed recording 开关开启/关闭时，`sync_versions` / `sync_outbox` 写入行为正确切换。
  - auth 删除统一进入回收站，恢复后重新回到活动列表。
  - 回收站 auth 不会被活动 `List()` / `syncAuthFromDatabase()` / reload 当成活动记录。
  - distributed cleanup 与 usage cleanup 的管理入口能清理目标数据且不留下内存残影。
  - `usage-history` YAML 配置与默认值能稳定驱动 CleanupWorker retention。
- 这轮必须覆盖的失败模式:
  - 关闭 distributed recording 后仍然写 outbox/version。
  - 某条删除链路仍调用硬删除。
  - usage 清理后 `defaultRequestStatistics` 仍残留旧明细。
  - distributed cleanup 把 outbox 清理和 versions reset 混成一个无法区分的动作。
  - 回收站 purge / restore 只改文件系统或只改 DB，导致双状态不一致。
  - 已在 `.trash` 的 auth 再次进入软删除，或 `authDir` 缺失时直接报错，导致 closeout/维护链在边界条件下失去幂等性。

## 单元测试设计

### UT-001

- 目标:
  - 验证 distributed recording 开关生效。
- 覆盖函数/模块:
  - `internal/store/postgresstore.go`
  - `internal/store/distributed_sync.go`
- 输入:
  - `recording-enabled=true/false` 两组配置，触发 config/auth 写路径。
- 预期输出:
  - 关闭时不再调用 distributed change 记录；开启时维持既有行为。
- 失败表现:
  - 关闭后仍生成 outbox/version 或开启后意外失去既有记录。

### UT-002

- 目标:
  - 验证 auth 删除改为回收站语义，并覆盖 management/runtime/service 三条链路。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files.go`
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
  - `sdk/cliproxy/service_auth_maintenance.go`
  - `internal/store/postgresstore.go`
- 输入:
  - 单文件删除、批量删除、runtime 自动删除、maintenance 删除。
  - already-in-trash auth path、`authDir` 缺失、以及文件在 move 前后可能消失的兜底分支。
- 预期输出:
  - 文件移到 `.trash/`，store 记录同步更新，活动 auth 被禁用且不再出现在活动列表。
- 失败表现:
  - 任一链路继续 `os.Remove` 硬删或 store/file 状态不一致。
  - 已在 `.trash` 的文件被重复搬运，或 `authDir` 缺失时没有退回到 token record 清理。

### UT-003

- 目标:
  - 验证 usage 手动清理与内存 reset。
- 覆盖函数/模块:
  - `internal/api/handlers/management/usage.go`
  - `internal/usage/logger_plugin.go`
  - `internal/usage/hot_buffer.go`
  - `internal/usage/write_queue.go`
- 输入:
  - 构造 PG mode / memory mode 下的历史数据与内存统计，再调用清理接口。
- 预期输出:
  - PG、HotBuffer、`defaultRequestStatistics` 同步清空或按 before 条件收敛。
- 失败表现:
  - API 返回成功但 snapshot 仍残留旧明细。

### UT-004

- 目标:
  - 验证 distributed cleanup 对 outbox / versions 的分离语义。
- 覆盖函数/模块:
  - `internal/api/handlers/management/distributed_sync.go`
  - `internal/store/distributed_sync.go`
- 输入:
  - `before=YYYY-MM-DD`
  - `resource=config,auth`
- 预期输出:
  - outbox 按时间删除；versions 按资源精确 reset；非法资源被拒绝。
- 失败表现:
  - outbox / versions 不能区分，或非法资源被静默吞掉。

### UT-005

- 目标:
  - 验证 `usage-history` YAML 配置默认值与显式值解析。
- 覆盖函数/模块:
  - `internal/config/config.go`
- 输入:
  - 空配置文件
  - 显式 `usage-history.retain-days / aggregate-retain-days`
- 预期输出:
  - 默认值分别回落到 `30 / 365`；显式值按配置生效。
- 失败表现:
  - 默认值丢失、0 值未回落、显式值未生效。

## 属性测试设计

### PT-001

- 性质:
  - 回收站路径映射是可逆且不会逃逸 `auth-dir`。
- 输入空间:
  - 普通文件名、带子目录的相对路径、异常路径边界。
- 不变量:
  - 活动路径 -> trash 路径 -> restore 路径 后，应回到原始相对路径；任何路径都不能越出 `auth-dir`。
- 预期失败模式:
  - 非法路径逃逸、restore 后路径错位、活动/回收站冲突。
