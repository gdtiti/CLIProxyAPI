## 测试目标

- 需要被保护的核心行为:
  - 新配置字段默认 `0` 时保持旧行为。
  - 命中 quota 检查间隔时，management hook 会主动请求 usage API。
  - usage API 返回 `401` 时删除 auth 文件并禁用运行态 auth。
  - usage API 返回非 `401` 时不误删。
- 这轮必须覆盖的失败模式:
  - 与既有 `codex-max-request-count` 逻辑双计数。
  - interval 关闭时仍误发起 probe。
  - probe 触发后非 `401` 仍误删账号。

## 单元测试设计

### UT-001

- 目标:
  - 验证 `AuthMaintenanceConfig` 默认值和显式 `codex-quota-check-request-interval` 配置加载。
- 覆盖函数/模块:
  - `internal/config.LoadConfigOptional`
- 输入:
  - 不包含新字段的配置。
  - 包含 `codex-quota-check-request-interval` 的显式配置。
- 预期输出:
  - 默认值为 `0`。
  - 显式值被原样保留。
- 失败表现:
  - 新字段丢失、默认值错误或 YAML 解析失败。

### UT-002

- 目标:
  - 验证命中 quota 检查间隔且 usage API 返回 `401` 时，auth 文件被删除。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - `codex-quota-check-request-interval=2`
  - 文件型 `codex` auth，携带 `access_token`、`account_id` 和本地测试 `base_url`
  - 第 2 次请求时 usage API 返回 `401`
- 预期输出:
  - 第 1 次请求后文件保留。
  - 第 2 次请求后文件被删除，运行态 auth 被禁用。
- 失败表现:
  - 未触发 probe、`401` 后仍保留文件，或删除后运行态未禁用。

### UT-003

- 目标:
  - 验证命中 quota 检查间隔但 usage API 返回非 `401` 时，auth 不被删除。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - `codex-quota-check-request-interval=2`
  - usage API 返回 `200`
- 预期输出:
  - auth 文件保留，运行态 auth 仍可用。
- 失败表现:
  - 非 `401` 也误触发删除。
