## 实际改动摘要

- 本轮改动:
  - 为 `auth-maintenance` 新增 `codex-quota-check-request-interval` 配置项，`0` 表示关闭。
  - 扩展 `AuthMaintenanceConfig` 与配置加载测试，并把该字段纳入运行态配置快照判定。
  - 将 management runtime hook 中原先单独的“按累计请求次数删除”收敛为统一的 `handleCodexRequestMaintenance` 入口。
  - 命中 `codex-max-request-count` 时优先删除；未命中删除阈值时，按 `codex-quota-check-request-interval` 触发 quota probe。
  - quota probe 复用 `executor.NewCodexExecutor(...).HttpRequest(...)`，只在 probe 返回 `401` 时删除 auth；非 `401` 或 probe 失败仅记录 warning 并保留账号。
  - 补充配置测试、service 测试、management runtime hook 定向测试，并更新示例配置与运行态维护 wiki。

## 风险、阻塞与未验证项

- 风险:
  - quota probe 依赖 `api_key/access_token` 与 `account_id`；缺失时当前实现选择跳过 probe，避免发起无鉴权请求导致误删。
  - 若同时配置 `codex-max-request-count` 和 quota probe 间隔，当前实现以累计次数删除优先；达到上限后不会再执行 probe。
- 阻塞:
  - 无功能性阻塞。
- 未验证项:
  - 未修复 management 包既有失败测试，因此未拿到该包全量通过结果。
