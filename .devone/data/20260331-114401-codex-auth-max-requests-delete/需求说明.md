## 问题定义

- 当前问题:
  - 当前项目只有按 `401` 阈值删除、按 `codex usage_limit_reached` 禁用等运行态维护能力，还没有“按累计请求次数删除 codex 文件 auth”的配置项。
- 影响对象:
  - `codex` 类型、文件落盘、由 management runtime hook 接管删除/禁用的 auth 文件。
- 触发背景:
  - 需要控制单个 `codexcli` 认证文件的最大可使用次数，达到上限后自动删除，避免文件被无限复用。
- 为什么现在处理:
  - 现有维护框架已经具备配置层与删除链路，本次只需补一个累计计数阈值即可闭环。

## 目标与成功标准

- 目标 1:
  - 增加一个可配置项，用于定义单个 `codex` 文件 auth 的最大累计请求次数。
- 目标 2:
  - 当该配置值大于 `0` 时，任一 `codex` 文件 auth 的累计请求次数达到阈值后自动删除对应认证文件，并在运行态内禁用该 auth。

## 范围边界

### 本次必须完成

- 配置结构新增累计请求阈值字段，默认 `0` 表示关闭。
- `codex` 文件 auth 在请求结果回调中累计请求次数，并在达到阈值后复用现有删除链路。
- 补齐最小单元测试，覆盖启用和关闭两种行为。

### 本次明确不做

- 不新增新的后台扫描线程或第二套删除通道。
- 不修改非 `codex` provider 的 auth 行为。
- 不改变现有 `401` 阈值删除与 `usage_limit_reached` 禁用逻辑。

## 验收真相陈述

- [REQ-001] 配置文件支持声明 `auth-maintenance` 下的 codex 累计请求删除阈值，未配置或配置为 `0` 时保持旧行为。
- [REQ-002] 当 `codex` 文件 auth 的累计请求次数达到阈值后，认证文件会被自动删除，且运行态 auth 被标记为禁用。

## 约束与依赖

- 技术约束:
  - 必须复用现有 `auth-maintenance` 和 management runtime hook，不引入隐藏回退。
- 业务约束:
  - 只统计 `codexcli` 文件 auth 的请求次数，不扩展到 API key 或其他 provider。
- 外部依赖:
  - 依赖现有 auth manager、management handler、配置加载与测试框架。

## 风险与待确认项

- 风险:
  - 请求计数需要跨进程重启可恢复，否则累计阈值会失真。
- 待确认:
  - 本轮按“累计所有已完成请求，不区分成功/失败”实现；这符合“账号请求累计次数”的字面需求。
