## 测试目标

- 需要被保护的核心行为:
  - `codex` 文件 auth 在达到累计请求阈值前不应被提前删除。
  - 达到阈值后必须删除文件并禁用运行态 auth。
  - 阈值为 `0` 时必须保持旧行为。
- 这轮必须覆盖的失败模式:
  - success 结果不计数导致阈值永远不触发。
  - 误删 generic `codex 429` 或非启用配置场景。

## 单元测试设计

### UT-001

- 目标:
  - 验证启用 `codex-max-request-count` 后，累计请求达到阈值会删除 auth 文件。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - `codex-max-request-count=2`
  - 同一个 `codex` 文件 auth 连续两次 `MarkResult`
- 预期输出:
  - 第 1 次后文件仍存在
  - 第 2 次后文件被删除，auth 被禁用
- 失败表现:
  - 文件提前删除、未删除或 auth 未禁用

### UT-002

- 目标:
  - 验证阈值为 `0` 时新逻辑关闭。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - `codex-max-request-count=0`
  - 同一个 `codex` 文件 auth 连续多次 `MarkResult`
- 预期输出:
  - 文件始终保留
  - auth 不因累计次数而被禁用
- 失败表现:
  - 默认关闭状态仍触发删除
