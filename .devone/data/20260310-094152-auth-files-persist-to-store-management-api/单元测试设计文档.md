## 测试目标

- 需要被保护的核心行为:
  新接口要把 `cfg.AuthDir` 下纳入范围的 auth 文件批量交给 `PersistAuthFiles`，
  并返回稳定的同步结果计数。
- 这轮必须覆盖的失败模式:
  当前 store 不支持 `PersistAuthFiles`；目录枚举或持久化失败时错误语义清晰，且
  不会伪造成功响应。

## 单元测试设计

### UT-001

- 目标:
  验证 `POST /v0/management/auth-files/persist-to-store` 成功时会枚举 authDir 下
  的 auth `.json` 文件，并一次性调用 store persister。
- 覆盖函数/模块:
  `PostPersistAuthFilesToStore`、auth file 枚举 helper、`tokenStoreWithBaseDir`
- 输入:
  临时 authDir 中放置两个 `.json` auth 文件和一个非 `.json` 噪音文件；store
  persister 返回成功。
- 预期输出:
  返回 200；响应体包含 `ok=true`、`target=auth-files`、`source=local`、
  `store_sync=true`、`total=2`、`persisted=2`；persister 仅收到两个 auth 文件路
  径。
- 失败表现:
  非 `.json` 文件被误同步，或返回成功但 persister 未收到完整路径集合。

### UT-002

- 目标:
  验证当前 store 不支持 `PersistAuthFiles` 时返回明确错误。
- 覆盖函数/模块:
  `PostPersistAuthFilesToStore`
- 输入:
  handler 使用一个不实现 `authFilesStorePersister` 的 token store。
- 预期输出:
  返回 409；响应体包含类似 `persist_not_supported` 的错误标识。
- 失败表现:
  接口错误返回 200，或错误语义与既有 management API 风格不一致。

### UT-003

- 目标:
  验证 store 持久化失败时接口返回 500 且不谎称成功。
- 覆盖函数/模块:
  `PostPersistAuthFilesToStore`
- 输入:
  authDir 中存在至少一个有效 auth 文件；store persister 返回错误。
- 预期输出:
  返回 500；响应体包含持久化失败错误；`ok` 不为 true。
- 失败表现:
  接口返回 200，或响应体仍声称 `persisted > 0`。
