## 测试目标

- 需要被保护的核心行为:
  - 阶段 1：配置驱动的 selector 选择、热更新与 invalid request blocker 行为正确
  - 阶段 1 追加：runtime auth maintenance 对 `429` / quota exceeded 只禁用不删除
  - 阶段 2：Codex 请求转换语义不变，但减少重复解析/重复整段序列化
  - 阶段 3：request-audit hook 默认不影响主请求链路
  - 阶段 4：Codex HTTP/WS 头部增强不破坏当前关键链路
- 这轮必须覆盖的失败模式:
  - selector 配置接线失效
  - simhash 元数据缺失或错误阻断普通请求
  - `429` / quota exceeded 被错误推进到自动删除
  - translator 优化导致 tool/function/schema 行为回退
  - audit hook 发送失败影响主请求
  - header 改动破坏现有 session/originator/metadata 行为

## 单元测试设计

### UT-001

- 目标:
  - 验证 `success-rate` selector 的配置接线与结果反馈生效
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/success_rate_selector.go`
  - `sdk/cliproxy/builder.go`
  - `sdk/cliproxy/service.go`
- 输入:
  - 不同 auth 的 success/failure 结果、不同路由配置
- 预期输出:
  - selector 能按成功率偏向更优 auth，并支持热更新
- 失败表现:
  - 仍退回 round-robin，或配置无效

### UT-002

- 目标:
  - 验证 `simhash` selector、request simhash 元数据与 request blocker
- 覆盖函数/模块:
  - `sdk/cliproxy/auth/simhash.go`
  - `sdk/cliproxy/auth/simhash_selector.go`
  - `sdk/cliproxy/auth/request_blocker.go`
  - `sdk/cliproxy/auth/conductor.go`
- 输入:
  - 相似/不相似请求体、无效请求错误、可用 auth 池
- 预期输出:
  - 相似请求稳定路由；已确认无效请求体可被阻断
- 失败表现:
  - 普通请求被误阻断，或 simhash 路由不稳定

### UT-002A

- 目标:
  - 验证 runtime auth maintenance 对 `429` / quota exceeded 采用 disable，而不是 delete
- 覆盖函数/模块:
  - `sdk/cliproxy/service_auth_maintenance.go`
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - generic `429`
  - `delete-status-codes: [429]`
  - quota exceeded / `Quota.BackoffLevel` 状态
- 预期输出:
  - auth 文件保留，但会被写成 `disabled=true`
  - delete 判定不再接管 `429` / quota exceeded
- 失败表现:
  - auth 文件被删除，或 `429` / quota exceeded 仍走 delete reason

### UT-003

- 目标:
  - 验证 Codex request fast path 与 legacy 语义等价
- 覆盖函数/模块:
  - `internal/translator/codex/openai/chat-completions/codex_openai_request.go`
  - `request_cache.go`
- 输入:
  - 包含 messages/tools/tool_choice/response_format/text 的典型请求
- 预期输出:
  - 新旧实现关键语义一致，并保留当前仓库关键兼容逻辑
- 失败表现:
  - tool/function/schema/verbosity/output 结构回退

### UT-004

- 目标:
  - 验证 parsed request cache 命中、更新与淘汰行为
- 覆盖函数/模块:
  - `request_cache.go`
- 输入:
  - 重复请求与多样请求序列
- 预期输出:
  - 相同原始请求可复用解析结果，缓存行为可预测
- 失败表现:
  - 重复解析、缓存污染或淘汰异常

### UT-005

- 目标:
  - 验证 request-audit hook 在 enabled / disabled 下的行为
- 覆盖函数/模块:
  - `internal/audit/hook.go`
  - `sdk/cliproxy/builder.go`
  - `sdk/cliproxy/auth/conductor.go`
- 输入:
  - 空配置、有效 endpoint、队列已满、provider 过滤场景
- 预期输出:
  - hook 仅在启用时发事件，失败只 warning，不阻断主链路
- 失败表现:
  - 请求失败、阻塞或事件过滤错误

### UT-006

- 目标:
  - 验证 Codex HTTP/WS header 拟真增强
- 覆盖函数/模块:
  - `internal/runtime/executor/codex_executor.go`
  - `internal/runtime/executor/codex_websockets_executor.go`
- 输入:
  - API key / 非 API key、gin headers、有无显式 metadata、mimic off/safe/strict、compact 请求场景
  - strict 下 `force-turn-metadata` / `force-turn-state` / `include-timing-metrics` 开关组合
- 预期输出:
  - 头部按锁定设计生效，且现有关键行为不回退
  - mimic 模式下 `/v1/responses/compact` 不再走上游真实 `/responses/compact`
  - strict 额外开关只在未显式提供客户端头时补缺省值
- 失败表现:
  - 缺 header、metadata 错误、现有兼容逻辑被覆盖、compact 仍命中上游 `/responses/compact`
