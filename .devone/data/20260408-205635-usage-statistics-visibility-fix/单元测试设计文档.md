## 测试目标

- 需要被保护的核心行为:
  - PG `QuerySnapshot` 返回聚合时仍包含 `details`。
  - `range=all` 不再回落为默认 24h。
  - 前端在 details 缺失时走聚合回退。
- 这轮必须覆盖的失败模式:
  - `details` 缺失导致过滤后数据清零。
  - 前端图表依赖明细时显示空白。

## 单元测试设计

### UT-001

- 目标: 验证 PG 快照可回填明细。
- 覆盖函数/模块: `internal/usage/query.go` (`QuerySnapshot` / 辅助查询函数)。
- 输入: 构造 `usage_aggregates` + `usage_details` 同窗口数据。
- 预期输出: `model.details` 非空，且聚合计数与明细统计一致。
- 失败表现: 仅返回聚合字段、details 为空。

### UT-002

- 目标: 验证 `parseTimeRange` 支持 `all`。
- 覆盖函数/模块: `internal/api/handlers/management/usage.go`。
- 输入: `range=all`。
- 预期输出: 起始时间为固定早期时间点（非 now-24h）。
- 失败表现: 仍回落 24h。

### UT-003

- 目标: 验证前端无 details 回退逻辑。
- 覆盖函数/模块: `src/utils/usage.ts`。
- 输入: 仅有聚合字段、无 details 的 usage 响应。
- 预期输出: 过滤后仍有数据用于卡片/趋势计算。
- 失败表现: 过滤结果为空。

## 属性测试设计

### PT-001

- 性质: 时间过滤对“有 details”和“无 details 回退”两分支都应输出非负聚合值。
- 输入空间: 不同时间窗口（24h/7d/30d/all）与随机 token 计数。
- 不变量: 请求数与 token 统计不应为负，且不因缺 details 直接归零。
- 预期失败模式: 分支不一致导致某些窗口空白。
