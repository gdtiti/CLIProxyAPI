## 测试目标

- 需要被保护的核心行为:
  - 新环境变量可以稳定控制自动重载开关与间隔。
  - 周期性自动重载在配置变化与未变化两种路径下走对分支。
  - 认证文件全量重建采用分批并发后，最终结果完整且提交原子。
  - auth refresh 不再重复扫描认证目录。
- 这轮必须覆盖的失败模式:
  - 环境变量非法值导致异常行为。
  - 自动重载重复触发 config reload。
  - 批量并发载入中出现单批失败后仍提交部分状态。
  - `forceAuthRefresh` 但未重建 file cache，导致 auth 结果过期。

## 单元测试设计

### UT-001

- 目标:
  - 验证 `CLIPROXY_AUTO_RELOAD_INTERVAL_SECONDS` 环境变量覆盖逻辑。
- 覆盖函数/模块:
  - `internal/config/config.go`
- 输入:
  - 空值、`0`、负数、正整数、非法字符串
- 预期输出:
  - 空值或 `<= 0` 时关闭自动重载
  - 正整数时写入正确秒数
  - 非法字符串返回明确错误或被当前配置加载路径显式拒绝
- 失败表现:
  - 自动重载配置被误开或误关

### UT-002

- 目标:
  - 验证 watcher 周期性 tick 在配置未变化时仅执行 auth refresh。
- 覆盖函数/模块:
  - `internal/watcher`
- 输入:
  - 固定 config hash，无 config 文件变更
- 预期输出:
  - 不走完整 config reload
  - 仅刷新 auth 相关状态
- 失败表现:
  - 一次 tick 触发额外全量 config reload

### UT-003

- 目标:
  - 验证配置变化时自动轮询能走现有 config reload 路径。
- 覆盖函数/模块:
  - `internal/watcher/config_reload.go`
- 输入:
  - 模拟 config hash 变化
- 预期输出:
  - config reload 被触发
  - 不会额外再执行一次重复 auth 全量扫描
- 失败表现:
  - 双重 reload 或状态不一致

### UT-004

- 目标:
  - 验证认证文件重建改为分批并发后，缓存结果完整且稳定。
- 覆盖函数/模块:
  - `internal/watcher/clients.go`
- 输入:
  - 多个认证文件，数量超过单批阈值
- 预期输出:
  - 所有文件都被处理
  - 提交前不会暴露部分完成状态
- 失败表现:
  - 最终缓存缺文件、重复文件或顺序依赖导致结果不稳定

### UT-005

- 目标:
  - 验证 `refreshAuthState` 优先复用 file cache，不再走额外的文件 synth 扫描。
- 覆盖函数/模块:
  - `internal/watcher/dispatcher.go`
- 输入:
  - 已构建 file auth cache 的 watcher 状态
- 预期输出:
  - 使用 cache 生成 auth 视图
  - 文件扫描计数不增加
- 失败表现:
  - 一次 refresh 仍重复全量扫描认证目录

## 属性测试设计

### PT-001

- 性质:
  - 无论认证文件总数如何分布到不同批次，最终聚合结果应等价于单线程全量处理结果。
- 输入空间:
  - 认证文件数量 0..N
  - 文件内容合法与非法混合
  - 不同批次边界与排序
- 不变量:
  - 最终 cache 集合完整
  - 错误时不提交部分状态
- 预期失败模式:
  - 批次切分导致结果缺失或重复

## 测试夹具与数据策略

- 夹具:
  - 临时目录下构造 config 文件与 auth 文件集合
  - 必要时注入假的 hash 检查或文件扫描计数器
- 真实数据策略:
  - 以真实文件系统读写为主，不使用纯内存假路径替代 watcher 的文件读取行为
- 禁止使用的假路径:
  - 不允许只断言函数被调用而不验证最终 cache 和 reload 结果
  - 不允许通过静默 mock 绕过文件扫描路径
