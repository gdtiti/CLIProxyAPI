## 问题定义

- 当前问题:
  - 当前仓库已具备 watcher、手动重载、auth runtime hook、runtime persistence、distributed sync 等能力，但仍缺少按固定秒数自动轮询重载配置和认证文件列表的能力。
  - 当前全量认证文件重载路径存在重复扫描 `authDir` 的问题，`reloadClients` 重建文件缓存后，`refreshAuthState` 仍会再次走 `FileSynthesizer`，在认证文件数量较大时会放大启动和重载卡顿。
  - 当前认证文件全量载入以同步串行路径为主，面对大量认证文件时容易造成明显阻塞。
- 影响对象:
  - `internal/watcher`
  - `internal/config`
  - `sdk/cliproxy`
  - 启动阶段和周期性重载阶段的认证文件处理链路
- 触发背景:
  - 用户要求在完成当前工作后追加任务，参考 `J:\_Dev\_me\_cpa\CLIProxyAPI-Arron196`，吸收其中与性能优化、认证文件自动检查和禁用相关的设计思想，同时新增环境变量控制自动重载间隔。
- 为什么现在处理:
  - 当前仓库与参考仓库 watcher 主干接近，但已存在更多运行时与分布式能力，越晚修正 watcher 重载模型，后续叠加能力时越容易放大性能回归和一致性问题。

## 目标与成功标准

- 目标 1:
  - 基于当前仓库而不是回退到参考仓库，实现一个可配置的周期性自动重载机制。
- 目标 2:
  - 将认证文件列表载入改为分批并发处理，并避免全量重载时重复扫描认证目录。
- 目标 3:
  - 保持现有 auth runtime、cooldown、distributed sync 等能力不回退、不静默降级。

## 范围边界

### 本次必须完成

- 分析 `CLIProxyAPI-Arron196` 中 watcher 相关设计，并明确可吸收与不可直接照搬的部分。
- 新增环境变量 `CLIPROXY_AUTO_RELOAD_INTERVAL_SECONDS`，用于控制每多少秒自动重载配置文件和认证文件列表。
- 在 watcher 内实现周期性自动重载逻辑：
  - 配置有变化时走现有配置重载路径。
  - 配置无变化时仅刷新认证文件状态，避免双重全量重载。
- 将认证文件列表全量载入改为分批次并发处理，降低大批量认证文件下的阻塞感。
- 优化 auth 状态刷新链路，优先复用已构建的文件缓存，避免重复全量扫描 `authDir`。

## 风险与待确认项

- 风险:
  - 周期性重载若与文件系统事件重载并发，可能引入锁竞争或重复刷新，需要严格复用现有串行化与去重机制。
  - 分批并发载入若批次大小选择不当，可能导致 CPU 峰值过高或 I/O 放大。
  - 认证文件缓存复用若遗漏 config 驱动的 synth 变化，可能导致 auth 状态过时。
- 待确认:
  - 本轮默认将自动重载间隔的单位固定为秒，不额外支持更复杂的时间格式。
  - 本轮默认将批次大小作为内部常量，不额外暴露第二个环境变量，除非实现中证明确有必要。
