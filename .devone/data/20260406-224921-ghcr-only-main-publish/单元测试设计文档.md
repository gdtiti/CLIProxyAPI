## 测试目标

- 需要被保护的核心行为: `docker-image` workflow 能在不依赖 DockerHub secrets 的前提下，为正式发布场景生成 GHCR 多架构镜像标签。
- 这轮必须覆盖的失败模式: 残留 `DOCKERHUB_*` 变量；缺失 `packages: write`；YAML 结构错误；丢失 `latest` / 版本标签之一。

## 单元测试设计

### UT-001

- 目标: 静态检查 `docker-image.yml` 中的登录与发布目标是否完全切换到 GHCR。
- 覆盖函数/模块: `.github/workflows/docker-image.yml`
- 输入: workflow 文本内容
- 预期输出: 仅出现 `ghcr.io`、`github.actor`、`secrets.GITHUB_TOKEN`、`packages: write` 等 GHCR 配置，不再出现 `DOCKERHUB_`。
- 失败表现: 仍有 DockerHub env/secrets/login/cleanup 片段。

## 属性测试设计

### PT-001

- 性质: 在 `workflow_dispatch` 与 `push tags v*` 两类触发下，workflow 的镜像标签生成逻辑保持稳定。
- 输入空间: `github.ref_name = main`、`github.ref_name = vX.Y.Z`
- 不变量: 都会生成 `latest` 与 `${VERSION}` 两个标签，并对 `linux/amd64` + `linux/arm64` 同时发布。
- 预期失败模式: 只生成单架构、缺少版本标签或缺少 latest 标签。

- 夹具: 当前仓库中的 workflow YAML 文本。
- 真实数据策略: 使用真实文件 diff、真实 `git grep` / YAML 解析结果；若触发远端 workflow，则基于真实 GitHub Actions run 结果。
- 禁止使用的假路径: 不伪造 workflow 成功，不用手写“理论通过”代替静态/远端证据。
