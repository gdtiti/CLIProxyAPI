## Wave 执行记录

### Wave 1

- 目标:
  实现 config/auth 分布式同步的 Phase 1 最小闭环，不把统计窗口缓存混入同一波
  次。
- 改动:
  1. 在 `Config` 中新增 `DistributedSyncConfig`、Redis 配置与默认 channel /
     poll interval helper，并在 `config.example.yaml` 暴露示例配置。
  2. 新增 `internal/store/distributed_sync.go`，封装
     `DistributedChange`、`DistributedChangeNotifier`、
     `EnsureDistributedSchema`、`GetDistributedVersions`、事务 helper 以及
     `recordDistributedChangeTx`。
  3. 改造 `PostgresStore` 写路径：`PersistConfig`、`PersistAuthFiles`、
     `Save`、`Delete` 只在真实内容变化时才记录 distributed change，避免回灌
     风暴。
  4. 新增 Redis notifier 与 distributed sync manager；manager 启动时先做
     PostgreSQL version reconcile，再订阅 Redis，并通过轮询做漏事件补偿。
  5. 在 `sdk/cliproxy/service.go` 中接入 notifier/manager 的启动与关闭，保
     证服务生命周期内自动管理分布式同步组件。
  6. 新增 `internal/store/distributed_sync_test.go` 与
     `internal/distributedsync/manager_test.go`，覆盖版本推进、批量 auth 同
     步、重复/自发事件过滤和轮询补偿。
  7. 收敛 `go.mod`：恢复 `toolchain go1.24.3`，并把 `go-redis` /
     `go-sqlmock` 记录为直接依赖。
- 结果:
  config/auth 更新现在具备“PostgreSQL 真相源提交 + Redis 事件通知 +
  PostgreSQL 轮询补偿”的最小闭环；统计窗口能力仍保留在后续阶段，不在本轮
  声称已实现。

## 风险、阻塞与未验证项

- 风险:
  1. 当前是资源级 reload，不是细粒度 patch；频繁变更时会带来更多 reload 开
     销。
  2. Redis 发布失败不会阻塞 PostgreSQL 提交，正确性依赖后续轮询补偿而不是
     强一致推送。
  3. 统计窗口缓存尚未实现，本轮只完成 Phase 1。
- 阻塞:
  无。
- 未验证项:
  1. 未在真实多节点 + 真实 PostgreSQL / Redis 环境中做联机验证。
  2. 未补 property test / fuzz test。
  3. 当前终端环境缺少 `docker` / `docker compose` CLI，未对同机双容器模板执行
     `docker compose config` 或 `up` 验证。
  4. 未实现月、日、24h、6h、3h 统计窗口刷新与缓存回填。
