### 阶段 1

- 目标:
  先把 config/auth 的“真相源提交语义”收紧，建立版本表与 outbox。
- 风险主题:
  config 当前是 watcher 异步 PersistConfig，提交语义弱于 auth，同步方案会
  先被它放大。
- 主要变更:
  统一配置与凭证写路径；写 DB 时同时更新版本和 outbox；保留现有
  reload-from-store 作为全量兜底。
- 验证方式:
  单元测试覆盖事务提交、事件幂等、版本跳跃降级；本地 2~3 节点集成测试覆
  盖节点重启和漏事件恢复。
- 完成标志:
  单节点写入后，其它节点可通过事件或补偿在可接受时间内收敛到一致状态。

### 阶段 2

- 目标:
  引入统计窗口缓存和管理面查询优化。
- 风险主题:
  统计窗口既要快，又不能与 PG 真相产生长期漂移。
- 主要变更:
  基于 PG 小时聚合生成 3h / 6h / 24h / 日 / 月窗口缓存；提供失效与重建策
  略；支持按 `instance_id` 或全局聚合查询。
- 验证方式:
  用固定样本校验窗口边界，覆盖跨日、跨月、UTC 边界场景；对 Redis miss /
  rebuild / repeated invalidate 做幂等验证。
- 完成标志:
  管理端能稳定返回多个统计窗口，且 Redis 故障不影响正确性，只影响时延。
