- 风险:
  1. 如果数据库写入与 Redis 版本/日志不是同一事务语义，会出现“DB 已更新
     但事件丢失”或“事件已发但 DB 未提交”。
  2. config 现有提交语义比 auth 弱，成功返回后到真正写入共享 store 之间存
     在 watcher 异步窗口。
  3. 仅做增量 patch 容易在节点漏事件、版本跳跃、节点重启后失去一致性。
- 待确认:
  1. 多节点是否允许同一配置对象并发写。
  2. 期望的一致性等级是秒级最终一致，还是管理端成功后必须全节点很快可见。
  3. Redis 是否允许使用 Stream / PubSub，以及是否接受引入 outbox 表。
