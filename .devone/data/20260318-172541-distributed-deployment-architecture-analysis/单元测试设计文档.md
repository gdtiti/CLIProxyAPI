## 测试目标

- 需要被保护的核心行为:
  config/auth 写入后的 version/outbox 语义、Redis 事件处理幂等性、漏事件轮询
  补偿，以及服务接线后的可编译性。
- 这轮必须覆盖的失败模式:
  无变化内容仍错误 bump 版本、重复事件重复 reload、自发事件回打自身、Redis
  事件丢失后版本无法追平。

## 单元测试设计

### UT-001

- 目标:
  验证 `PersistConfig` 在内容未变化时不会记录 distributed change。
- 覆盖函数/模块:
  `PostgresStore.PersistConfig`
  `recordDistributedChangeTx`
- 输入:
  数据库现存 config 内容与本地 config 文件完全一致。
- 预期输出:
  事务正常结束，但 notifier 不收到 distributed event。
- 失败表现:
  无实际变更仍 bump version/outbox，导致回灌风暴。

### UT-002

- 目标:
  验证 `PersistConfig` 在内容变化时会写入 version/outbox，并发布变更事件。
- 覆盖函数/模块:
  `PostgresStore.PersistConfig`
  `recordDistributedChangeTx`
  `publishDistributedChange`
- 输入:
  数据库旧内容与本地 config 文件不同。
- 预期输出:
  提交后拿到 `DistributedResourceConfig` 的新版本事件，payload 包含 config 标识。
- 失败表现:
  内容变化已落库，但版本或事件缺失。

### UT-003

- 目标:
  验证 `PersistAuthFiles` 会把多条 auth 文件变化收敛成单个批量 distributed
  event。
- 覆盖函数/模块:
  `PostgresStore.PersistAuthFiles`
  `syncAuthFileTx`
  `recordDistributedChangeTx`
- 输入:
  一条 auth upsert、一条 auth delete。
- 预期输出:
  生成 `DistributedResourceAuth` 的单个 sync 事件，payload 同时包含
  `upserted` 与 `deleted`。
- 失败表现:
  多文件变化拆成多次重复广播，或批量 payload 不完整。

### UT-004

- 目标:
  验证 manager 处理更高版本的外部事件时会执行一次 reload，并跳过重复事件。
- 覆盖函数/模块:
  `Manager.Start`
  `Manager.handleChange`
- 输入:
  同一个高版本 auth 事件连续投递两次。
- 预期输出:
  store/runtime 各只 reload 一次，本地版本推进到目标版本。
- 失败表现:
  重复事件触发重复 reload，或版本推进不正确。

### UT-005

- 目标:
  验证 manager 会忽略自发事件，但仍更新本地已知版本。
- 覆盖函数/模块:
  `Manager.handleChange`
- 输入:
  `NodeID` 与当前节点相同的 config 事件。
- 预期输出:
  本地版本推进，但不触发 store/runtime reload。
- 失败表现:
  节点消费自己发出的事件并重复回灌。

### UT-006

- 目标:
  验证 Redis 漏事件时，manager 仍可通过 PostgreSQL version 轮询补偿完成回灌。
- 覆盖函数/模块:
  `Manager.reconcileVersions`
  `Manager.runPollLoop`
- 输入:
  本地版本落后于 store 版本，且没有任何 Redis 事件输入。
- 预期输出:
  轮询触发 reload，最终版本追平。
- 失败表现:
  Redis 事件丢失后节点永久落后。

## 属性测试设计

### PT-001

- 性质:
  在乱序/重复事件条件下，节点最终状态由 PostgreSQL 中的最高已提交版本决定。
- 输入空间:
  不同版本、重复次数、乱序程度、节点启动时点。
- 不变量:
  本地已应用版本单调不减；即使 Redis 漏事件，也能通过 reconcile 自愈。
- 预期失败模式:
  版本回退、重复 apply、最终状态与 PostgreSQL 真相不一致。
- 当前状态:
  设计已记录，本轮未实现 property test。
