## 测试目标

- 需要被保护的核心行为:
  - `usage_limit_reached` 只禁用、不删除
  - generic `codex 429` 不禁用、不删除
  - `401` 连续失败达到阈值后删除
  - watcher 对内部写删文件具备抑制与去抖能力
- 这轮必须覆盖的失败模式:
  - 维护队列重复入队
  - watcher 监听内部删除导致重复清理
  - 配置缺省值错误导致维护循环行为异常

## 单元测试设计

### UT-001

- 目标:
  - 验证 `AuthMaintenanceConfig` 缺省值和显式配置加载。
- 覆盖函数/模块:
  - `internal/config.LoadConfigOptional`
- 输入:
  - 不包含 `auth-maintenance` 的配置
  - 包含显式 `auth-maintenance` 的配置
- 预期输出:
  - 缺省值被补齐；显式值被保留
- 失败表现:
  - 队列间隔/扫描间隔为零或配置值丢失

### UT-002

- 目标:
  - 验证 `usage_limit_reached` 只会产生禁用动作。
- 覆盖函数/模块:
  - `sdk/cliproxy/service.go` 维护 hook / candidate 逻辑
- 输入:
  - `codex` + `429` + `usage_limit_reached`
- 预期输出:
  - auth 文件保留但写入 `disabled=true`，内存 auth 被禁用
- 失败表现:
  - 文件被删除，或 generic 429 被误判

### UT-003

- 目标:
  - 验证 generic `codex 429` 不误禁用。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
  - `sdk/cliproxy/service.go`
- 输入:
  - `codex` + `429` + 普通 rate limit 文案
- 预期输出:
  - auth 保持可用
- 失败表现:
  - auth 被禁用或删除

### UT-004

- 目标:
  - 验证 watcher 对内部删除/写入的抑制与去抖。
- 覆盖函数/模块:
  - `internal/watcher/events.go`
  - `internal/watcher/watcher.go`
- 输入:
  - 同一路径连续 write/remove 事件
- 预期输出:
  - 只触发一次稳定处理，内部删除可被抑制
- 失败表现:
  - 重复 remove/addOrUpdate 或状态抖动

## 属性测试设计

### PT-001

- 性质:
  - 同一路径维护候选在 pending/in-flight 状态下不能重复入队。
- 输入空间:
  - 多次对同一路径 enqueue / pop / finish 的组合
- 不变量:
  - 同一时刻同一路径最多只有一个待处理 candidate
- 预期失败模式:
  - 重复删除或重复禁用
