## 测试目标

- 需要被保护的核心行为:
  - 配置可正确加载 `disable-status-codes`
  - 命中配置状态码时 auth 被禁用而不是删除
  - 空列表时 generic 状态码不误禁用
  - `usage_limit_reached` 既有 special disable 不回退
- 这轮必须覆盖的失败模式:
  - 配置字段存在但 YAML 不生效
  - service 层命中状态码后误删 auth 文件
  - disable 与 delete 同时配置时发生误删
  - management hook 与 service 层语义不一致

## 单元测试设计

### UT-001

- 目标:
  - 验证 `AuthMaintenanceConfig` 默认值和显式 `disable-status-codes` 配置加载。
- 覆盖函数/模块:
  - `internal/config.LoadConfigOptional`
- 输入:
  - 不包含 `auth-maintenance.disable-status-codes` 的配置
  - 包含 `disable-status-codes` 的显式配置
- 预期输出:
  - 默认空列表保持关闭
  - 显式列表被原样保留
- 失败表现:
  - 新字段丢失、默认值错误或 YAML 解析失败

### UT-002

- 目标:
  - 验证 service 层命中 `disable-status-codes` 时写盘禁用，不删除文件。
- 覆盖函数/模块:
  - `sdk/cliproxy/service_auth_maintenance.go`
- 输入:
  - `disable-status-codes: [429]`
  - `codex` 文件 auth 返回 generic `429`
- 预期输出:
  - auth 文件仍存在且 `disabled=true`
  - 运行态 auth 被标记为 disabled
- 失败表现:
  - 文件被删除，或运行态仍保持 enabled

### UT-003

- 目标:
  - 验证当同一状态码同时出现在 `disable-status-codes` 与 `delete-status-codes` 时，disable 优先。
- 覆盖函数/模块:
  - `sdk/cliproxy/service_auth_maintenance.go`
- 输入:
  - `disable-status-codes: [429]`
  - `delete-status-codes: [429]`
  - generic `429`
- 预期输出:
  - auth 文件被禁用而不是删除
- 失败表现:
  - 文件被误删

### UT-004

- 目标:
  - 验证 management runtime hook 命中 `disable-status-codes` 时同样禁用 auth。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
- 输入:
  - `disable-status-codes: [429]`
  - management hook 收到 generic `429`
- 预期输出:
  - auth 文件保留且写入 `disabled=true`
  - auth 状态为 disabled
- 失败表现:
  - management hook 忽略该配置或删除文件
