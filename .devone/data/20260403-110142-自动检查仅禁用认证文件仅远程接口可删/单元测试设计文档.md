## 测试目标

- 需要被保护的核心行为:
  - 所有自动链路触发后，认证文件仍存在，且文件内容/运行态状态都进入 disabled。
  - 远程直接删除接口仍是唯一会删除认证文件的路径，本轮不误伤该能力。
- 这轮必须覆盖的失败模式:
  - `401` 阈值仍删除文件。
  - `codex-max-request-count` 仍删除文件。
  - quota probe `401` 仍删除文件。
  - 兼容 delete 配置字段仍推动 delete candidate。
  - 历史 pending delete 状态没有被转成 disable。

## 单元测试设计

### UT-001

- 目标:
  - 验证 management runtime hook 的 `401` 阈值、`codex-max-request-count`、quota probe `401` 都改为禁用而非删除。
- 覆盖函数/模块:
  - `internal/api/handlers/management/auth_files_runtime_hook.go`
  - `internal/api/handlers/management/auth_files_runtime_hook_test.go`
- 输入:
  - 连续 `401`
  - `CodexMaxRequestCount > 0`
  - `CodexQuotaCheckRequestInterval > 0` 且 probe 返回 `401`
- 预期输出:
  - auth 文件仍存在
  - 文件写入 `disabled=true`
  - `auth.Disabled == true`
  - 状态消息变成 disable 语义
- 失败表现:
  - 文件不存在 / 被移入回收站 / 状态消息仍是 removed

### UT-002

- 目标:
  - 验证 service 层兼容 delete 配置与旧 pending delete 状态都只会禁用。
- 覆盖函数/模块:
  - `sdk/cliproxy/service_auth_maintenance.go`
  - `sdk/cliproxy/service_auth_maintenance_test.go`
- 输入:
  - `delete-status-codes`
  - `delete-quota-exceeded`
  - 连续 `401`
  - 旧 `auth_maintenance_pending_delete=true`
- 预期输出:
  - 进入 disable candidate / disable action
  - auth 文件保留
  - 运行态 auth disabled
- 失败表现:
  - 仍走 delete candidate 或文件被删
